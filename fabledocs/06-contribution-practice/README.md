# 06 — Contribution Practice

Learning ends where shipping begins. This module is graded work: junior tickets → cross-layer features → senior projects and katas. Every item includes contribution-realism (why a maintainer would accept or reject it) and an **Interview story potential** line — completed work here becomes your [STAR stories](../08-interview-prep/06-behavioral-star-stories.md).

| Page | Scope |
| --- | --- |
| [01-good-first-tickets.md](01-good-first-tickets.md) | 16 tickets, hours each: tests, small fixes, type tightening |
| [02-mid-level-feature-tickets.md](02-mid-level-feature-tickets.md) | 10 cross-layer tickets (schema→API→UI→tests), design notes required |
| [03-senior-build-projects.md](03-senior-build-projects.md) | 6 projects, days–weeks, with full engineering plans |
| [04-refactor-and-design-katas.md](04-refactor-and-design-katas.md) | 8 judgment katas: RFCs, migrations, boundary fixes |

Reality note: Outline is an active BSL-licensed product with strong conventions ([AGENTS.md](../../AGENTS.md)) and its own roadmap. Treat tickets here as *practice with realistic constraints*; before turning any into an upstream PR, search existing issues/PRs and open a discussion first ([maintainer communication](../07-career-and-collaboration/03-maintainer-communication.md)). Practice done on a fork is worth 90% as much as a merged PR for learning — and 100% as much for interviews if you're honest about it ("built on a fork of a production OSS codebase" is a fine sentence).
